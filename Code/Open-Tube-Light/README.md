# Open-Tube-Light Firmware

Firmware for the Open-Tube-Light LED tube fixture, running on an STM32H723VET6. It receives lighting data over Art-Net (Ethernet) or DMX512 (RS-485), maps it onto a segmented SK9822 LED strip, and shows status on an SSD1306 OLED.

## Capabilities

- Art-Net 4 input over Ethernet, multi-universe, with ArtPoll/ArtPollReply discovery and ArtSync
- DMX512 input over UART5 / RS-485 with DMA, break and idle detection, partial-universe support
- SK9822 output over SPI1 + DMA (ping-pong buffers), idle refresh every 150 ms
- Configurable segment count (logical DMX pixels mapped onto 144 physical LEDs), DMX start address, Art-Net Port-Address
- Failsafe on signal loss: hold last / zero / full
- Remote configuration from a companion app through custom ArtCommand verbs — see [docs/artnet-custom-protocol.md](docs/artnet-custom-protocol.md)
- Status display on SSD1306 OLED (I2C1 + DMA); 4 buttons wired, UI not implemented yet

## Stack

| Layer | Implementation |
|---|---|
| MCU | STM32H723VET6, Cortex-M7 @ 500 MHz (HCLK 250 MHz) |
| Peripheral framework | STM32CubeMX-generated HAL |
| RTOS | FreeRTOS via CMSIS-RTOS v2 |
| Network | LwIP, LAN8742A PHY (RMII) |
| Protocols | Art-Net 4, DMX512-A |
| LED output | SK9822 over SPI + DMA |
| Display | SSD1306 OLED over I2C + DMA |

## Architecture

```text
Art-Net (UDP, tcpip_thread) ─┐
                             ├─▶ dmx_input (driver vtable) ─▶ EffectTask ─▶ pixel_render ─▶ SK9822 SPI DMA ─▶ LED strip
DMX512 (UART5 ISR + DMA) ────┘
```

- **`ControlTask`** — initializes LwIP, starts the configured input driver, refreshes the OLED at 1 Hz.
- **`EffectTask`** — waits for a frame-ready flag (150 ms timeout), latches the latest DMX data, renders it, and starts the SPI DMA transfer. On timeout it refreshes the strip or applies the failsafe.

Startup: `main()` sets up MPU, caches, clocks and peripherals → `device_config` loads defaults → `ControlTask` brings up the network and input driver → the driver signals `EffectTask` on every new frame.

| Module | Role |
|---|---|
| `Core/Src/main.c` | Startup, task bodies, OLED status, HAL callbacks |
| `Core/Src/device_config.c` | Config model, defaults, validation, atomic patch/commit |
| `Core/Src/dmx_input.c` | Protocol-independent input manager — [docs/dmx-input-drivers.md](docs/dmx-input-drivers.md) |
| `Core/Src/Art-Net/` | UDP receive, packet handlers, ArtPollReply |
| `Core/Src/DMX512/dmx512_uart.c` | DMX512 receiver |
| `Core/Src/pixel_render.c` | DMX → segment → LED mapping, failsafe |
| `Core/Src/SK9822/sk9822.c` | LED strip driver |
| `Core/Src/OLED/ssd1306.c` | OLED driver (async I2C DMA) |

Memory placement (DTCM / non-cacheable D1 & D2 / MPU) is documented in [docs/memory-layout.md](docs/memory-layout.md).

## Default configuration

| Setting | Default |
|---|---|
| Short / long name | `OpenTubeLight` / `OpenTubeLight V0.1` |
| IP | Static `192.168.1.179/24` (set in CubeMX; `device_config` IP fields are not applied yet) |
| Pixels / segments / format | 144 / 144 / RGB |
| Input source | Art-Net |
| DMX start address | 1 |
| Art-Net Net / SubNet / Universe | 0 / 0 / 1 |
| Art-Net max refresh rate | 44 Hz |
| Failsafe | Hold last frame |

Configuration is runtime-only for now — changes are lost on reboot until flash persistence is implemented.

## Build

Requires the STM32Cube VS Code extension (provides `cube-cmake` and the arm-none-eabi toolchain).

```sh
cube-cmake --preset Debug          # configure (once, or after CMakeLists.txt changes)
cube-cmake --build --preset Debug  # → build/Debug/Open-Tube-Light.elf
```

Presets: `Debug`, `Release`. User sources are listed in the root `CMakeLists.txt`; `cmake/stm32cubemx/` is generated by CubeMX.

`Open-Tube-Light.ioc` is the source of truth for clocks, pins, DMA, NVIC, MPU, FreeRTOS and LwIP. Regenerate from CubeMX after changing it; only code inside `USER CODE BEGIN/END` blocks survives regeneration.
